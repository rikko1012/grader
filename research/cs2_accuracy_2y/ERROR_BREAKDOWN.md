## 2. Method

Multiplicative chain, exact (product = actual): `actual = lambda x (R/R_hat) x [(T/R)/(T_hat/R_hat)] x [(K/T)/(lambda/T_hat)]`
- R_hat = the model's rounds assumption (perf-2: 21.7413 x maps; cm-2 has no explicit rounds term: 21.7413 x maps x the partial
  effect of its two rounds-per-map features); R = realized rounds, split into regulation `sum min(rounds,24)` and overtime;
- T_hat = sum of the five teammates' projections (the model's implied team kills); T = realized team kills; team kills per round
  split into the part explained by realized round-win share (cubic OLS - an oracle mapping, "team strength / scoreline") and the rest;
- share = his kills / team kills vs his projection / team sum; HS adds HS-per-kill vs the model's.
Contributions: one-at-a-time, chained (rounds -> team -> share -> HS) and **Shapley over all orders** (headline). Log loss: the
spread multiplier re-fitted after each substitution (A3). Predictability: each realized ratio regressed on pre-match features
(51: the 14 cm-2 features, perf-2 parts, Elo, team / opponent rounds-per-map, round-win share, OT rate, team kills / conceded per
round, rest days, player share history, roster continuity, player's maps with this team, LAN, format, history depth) by gradient
boosting, trained on rows before each quarter and scored on the quarter (2025-07 .. 2026-10-21), loss weighted by lambda^2;
component predictions centred on their training mean; fixable = MSE / MAE removed when lambda is multiplied by the PREDICTED ratio.

Process note (disclosed): the first predictability run derived series format from the series score row; for BO1s that row holds the
round score, which leaked BO1 overtime into the `bo` feature (Map 1 "predictable" 2.4%). Found from the result itself, fixed in
`build.py`, everything downstream re-run; all numbers here are from the fixed run (Map 1 total predictable 0.55%).

## 4. Reproduce / resume

Checkpoints live in `scratchpad\cs2acc\ed1` (series.csv.gz, p1.csv.gz, pred_factors.csv.gz, the JSON results, tables.md); each step
reads the previous step's files, so any step can be re-run alone:

```
cd research/cs2_accuracy_2y/error_breakdown
S=<scratchpad>/cs2acc
python build.py      $S/codex_export $S/ed1                                     # ~75 s: rebuild cm-2 / perf-2 + realized + pre-match features
python p1_build.py   $S/codex_export/p1_units.json $S/under/p1_fc.json $S/codex_export $S/ed1/series.csv.gz $S/ed1
python hltv_decomp.py $S/ed1          # ~15-40 min: oracle decomposition, distribution, breakdowns
python predict.py    $S/ed1           # ~25-55 min: forward predictability (6 quarterly folds x 3 scopes)
python dist_shape.py $S/ed1           # gamma vs normal shape check (population a and real lines)
python p1_decomp.py  $S/ed1           # real-line decomposition, calibration, breakdowns (needs the three above)
python report_tables.py $S/ed1 > $S/ed1/tables.md
```
No .pkl is read; no production endpoint or database was contacted (the P1 forecast rows are UT-1's read-only pull).
