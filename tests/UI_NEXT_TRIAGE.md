# Legacy browser suites on the redesign: triage of the 107 failures (2026-11-12)

**PORTED 82 · OLD-ONLY 7 · REAL BUG 18 = 107**

The legacy browser suites run on the previous design (`UI_NEXT=0`, set by the `env` fixture in `tests/test_upgrade_browser.py`).
Pointed at the redesign (`html[data-ui=next]`, the default since 2026-11-11), 107 of their 587 tests failed. Each one is listed
below with exactly one outcome. The legacy tests are untouched and keep guarding the previous design.

- **PORTED**: the function exists on the redesign. An equivalent test in `tests/test_ui_next_ported_*.py` asserts the same
  behaviour and numbers with the redesign's selectors. The third column says what differed.
- **OLD-ONLY**: the test checks something that exists only in the previous layout. The third column gives the reason.
- **REAL BUG**: the redesign hid, cut or mis-sized something. It is fixed (rules appended to `web/upgrade-next.css`, one `NEXT`
  branch in `web/upgrade-hub.js`) and a ported test proves the fix. Display only: no grade, side, chance, stake or projection
  changed.

To run a legacy test on the redesign: `LEGACY_UI_NEXT=1 python -m pytest <test id>` (the fixture's default stays `0`).

## Re-run on this branch

All 107 with `LEGACY_UI_NEXT=1`: 84 still fail and 23 pass.

- The 84 are PORTED or OLD-ONLY below: they fail on the redesign by design (upper-cased labels, the ladder, 32px desktop controls,
  the gold sheet).
- 8 of the 23 pass because of this branch's fixes; they fail again with the fixes taken out. They are REAL BUG below.
- 15 of the 23 pass on c0c5b06 as it is. The listed run started at 01:29, before c0c5b06 was committed at 01:43; their failure
  (a desktop row's name too narrow to press or read) did not happen again in three runs, and its cause in that run was not
  found. They are PORTED: their legacy bodies now also run on the redesign from the ported files.

## Real bugs fixed

1. Phone / tablet rows with the Edge and H2H columns on (production flags): the base sheet's five-column phone grid outranked the
   redesign's row grid. The line sat on Scout's side, names were cut to two letters and the Lines button ran off the row.
   Fix: the redesign's grid wins (CSS).
2. Phone hit windows with H2H and Season on: the five windows ran past the card (Season cut at 360px; rows with no Scout side
   ran to 458px). Fix: five equal columns, label above value (CSS).
3. "Below break-even" was only in the Edge cell, which the redesign hides on the phone, while a card is open and at 1101-1279px.
   Fix: the Scout cell carries the same chip where the Edge column is hidden (`scoutCell` NEXT branch + CSS).
4. Phone / tablet rows with a long Scout cell: the first column was 0-20px. By player the row's Card button could not be
   pressed; By prop the stat name was printed over the Scout side. Fix: the first column keeps 96px and the Scout cell wraps (CSS).
5. Desktop 1101-1499px: names lost 42px to a face that is hidden there and were cut. Fix: the name takes the cell (CSS).
6. Desktop 1101-1180px: the Lines column was hidden, so a prop's other lines could not be opened from the board. Fix: it is
   shown, compact; L5 / L10 only up to 1279px; no Watch column at 1101-1180px (CSS).
7. Phone targets left at desktop height (the previous design guaranteed 40px): the card's "More ..." rows 32px, the Filters
   pop-over's Clear filters / Done 32px, Slips tabs 36px, Tracked slips "My picks", the Record sport menu and Retry 32px, the
   toolbar's Best prices 32px. Fix: 44px at 1100px and below (CSS).
8. Slip: the leg below its break-even lost its red line (the slip rule set box-shadow:none on every leg). Fix: the line is
   back (CSS).

## Left open

`tests/test_ui_next_browser.py::test_rows_by_keyboard_and_no_shift_on_refresh` fails now and then (1 of 8 runs on c0c5b06 as it is,
before any change here): a repaint just after the board loads takes keyboard focus off the row's name before the test presses a
key. Not one of the 107 and not changed by this branch.
